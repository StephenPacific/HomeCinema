# HomeCinema 本地运行包

本包包含预构建网页、Node 服务、Mac 原生音频程序和可重建源码。运行时无需 `npm install`；前提是已经安装 Node.js 22.12 或更高版本。这是 macOS Apple Silicon 本地运行包，不是已经签名、公证的应用安装器。

## 启动与听音乐

1. 解压到一个可以写入的目录。不要在压缩包里直接启动。
2. 双击 `Start HomeCinema.command`，保留终端窗口。首次启动如提示缺少 Node.js，请安装官方 Node.js 后重新启动。
3. 用 Mac 浏览器打开终端显示的 Local 地址，默认 `http://localhost:4173/?source=live`。
4. 在 macOS 蓝牙设置中连接音箱。回到 HomeCinema 的 **System audio** 页面，刷新设备，选择 Mac 扬声器和已经连接的蓝牙音箱，再点 **Start system audio**。
5. 在 Mac 上用平常的音乐软件播放音乐。普通启动不会播放测试音；**Calibrate speakers first** 是可选的扫频校准，会播放短测试声音。
6. iPad、Windows 电脑等设备加入同一局域网，用浏览器打开页面显示的 Network 地址或扫描二维码，再点 **Enable live audio**。移动设备保持页面在前台。

如果本机默认端口已有 HomeCinema 服务，启动器只提示使用现有页面，不重复启动服务或采集声音。复制出一个新包不会替换当前正在运行的版本；切换到新包前，先停止旧包共享，再在旧终端按 Ctrl-C。

蓝牙配对由 macOS 管理；HomeCinema 不会自动配对，也不会把刚连接的设备自动加入正在运行的输出组。添加或更换输出时，停止共享、刷新设备并重新选择，然后启动。不同设备组合可能需要重新调整相对延迟。

## 哪些设备可以用

| 用法 | 当前实现 |
| --- | --- |
| Mac 系统音乐 → Mac 扬声器与已连接蓝牙音箱 | 已实现，当前这组设备已试听 |
| Mac 系统音乐 → iPad 浏览器 | 已实现，当前 iPad 已试听，反馈基本重合 |
| Mac 系统音乐 → Windows 浏览器 | 使用同一个网页接收路径；尚未在 Windows 真机验证 |
| Windows 上采集所有应用的系统声音并分发 | 尚未实现；本包的原生音频程序只支持 Mac |
| Windows 电脑连接自己的蓝牙音箱再播放网页声音 | 使用 Windows 当前音频输出；其额外蓝牙延迟需要另行试听、微调，尚未实机验证 |
| 多台蓝牙音箱同时接在一个 Mac 上 | 可选择多个 macOS 已识别输出；数量和稳定性取决于硬件，当前只验证了一个蓝牙音箱与 Mac 扬声器 |

Windows、手机和 iPad 接收时不需要安装本包，也不需要安装 Node.js；只打开 Mac 显示的局域网播放器地址。Windows 电脑无须通过蓝牙与 Mac 配对。

## 同步是怎样实现的

```text
Mac 音乐应用
    ↓ Core Audio 系统声音采集
    ├─ 原生输出组 → Mac / 蓝牙音箱
    └─ 带时间戳的 PCM → 本机 Node 服务 → 局域网浏览器 → iPad / Windows 扬声器
```

每段音频都有采集时刻和共同播放目标，默认约为采集后 700 ms。Mac 原生输出组预留相应延迟；网页接收端先与 Mac 对时，再把音频安排在同一目标时刻。提前收到的数据排队，过期数据丢弃，轻微时钟漂移缓慢修正。

700 ms 是从采集到约定出声的共同总目标。它让网络传输和缓存有时间完成。页面上的 **Timing estimate** 是软件调度估计；实际音箱和房间仍可能有剩余差异。接收端可以用 **Earlier / Later** 做 ±200 ms 微调。

当前软件检查包括 Node 离线测试、前端构建与原生时间线自测；当前 Mac / 蓝牙 / iPad 的普通音乐试听反馈为基本重合、明显改善。Windows 接收、更多蓝牙设备、睡眠唤醒及长时间稳定性仍需实机验证。

## 停止与退出

- **Stop sharing to all devices** 停止本机采集和所有实时接收，恢复 macOS 普通音频输出。音乐应用本身继续由你控制。
- 保留当前两小时会话上限；到时共享自动结束，需要重新启动共享。
- 终端里的 Ctrl-C 退出服务并清理它拥有的音频进程。
- 关闭网页不等于退出服务。电脑休眠、输出设备断开或接收浏览器进入后台可能中断音频。
- 所选 Mac／蓝牙输出断开或失去可用延迟信息时，当前共享组会结束并恢复普通输出。重新连接后刷新设备、重新选择并启动；当前版本不会自动把设备重新接入共享组。

## 包的兼容范围

- `bin/sfctl` 是 Apple Silicon / arm64 程序，在当前 macOS 26.3 上构建和运行。其系统音频接口要求 macOS 14.4+；更早于当前系统的兼容性尚未实机验证。Intel Mac 可以按源码说明重新构建，不能使用这个 arm64 程序。
- Node.js 不随包分发，避免依赖本机 Homebrew 动态库的运行时被错误复制。运行包已包含网页资源，无需安装前端构建依赖。
- 包中没有上传过的音乐、`.env`、局域网设备状态、当前会话补偿、访问令牌或运行日志。新启动后按实际设备重新选择；会话中的声学校准不持久保存。
- Node 服务使用内建模块。音频在本地内存和局域网中传输，不经过云端。
- 原生 SyncForge 上游使用 MIT 许可，原文随包提供。前端第三方许可随包提供；修改原生源码以 `native/syncforge-live.patch` 保存。

## 重建与高级启动

开发构建依赖以 `package-lock.json` 固定。安装兼容版本的 Node.js 后运行 `npm ci`、`npm run build`。原生源码设置与验证见 `docs/system-audio-live.md`，共同时间轴说明见 `docs/common-timeline-v1.md`。

可以通过 `PORT` 指定其他端口。启动器使用包内 `bin/sfctl`；开发环境也可以用 `SYNCFORGE_BIN` 或 `SYNCFORGE_DIR` 指向自行构建的原生程序。

包内校验清单列出 SHA-256 摘要，用于检查解压文件是否完整。
